## OCR configuration

- Vietnamese runs used PaddleOCR detection with `lang='vi'`, Tesseract with `lang='vie'`, and EasyOCR with `['vi']`.
- SROIE runs used PaddleOCR detection with `lang='en'`, Tesseract with `lang='eng'`, and EasyOCR with `['en']`. VietOCR was not used for SROIE.
- PaddleOCR document-orientation classification, document unwarping, and text-line orientation classification were disabled.
- Each returned PaddleOCR `dt_polys` polygon was converted to an axis-aligned bounding-rectangle crop. Crops were processed in the exact returned order; no extra reading-order sorting was applied.
- Nonempty recognition strings were joined with tab separators in the preserved crop order.
- VietOCR output was retained only when the predicted confidence was strictly greater than 0.8.
- Tesseract was called without an additional configuration string, so its default engine and page-segmentation settings were used.

## OpenCV reproduction guard (CHG-20261011-07)

Inspect the current interpreter without installing or removing anything:

    python code/analysis/check_opencv_environment.py

For a prospective clean environment, after installing its OCR dependencies:

    python code/analysis/check_opencv_environment.py --require-single-distribution

The second command returns exit 2 for missing/mismatched metadata or multiple
OpenCV distributions, even when one metadata version matches the runtime. It
does not change the environment. Use a separate fresh environment for future
installation validation; do not alter the active experimental venv or retrofit
existing checkpoint manifests. The observed runtime target is 4.10.0, not a
validated lockfile for all OCR dependencies.

OpenCV's official wheel instructions require selecting only one of its four
packages because they share cv2:
https://pypi.org/project/opencv-python/#installation-and-usage

`requirements.txt` specifies broad dependency ranges, not a bit-exact
reproduction recipe. Installing OCR dependencies can add another OpenCV wheel;
validate the final installed set and imported runtime rather than assuming the
range file or pip package metadata alone guarantees historical compatibility.
